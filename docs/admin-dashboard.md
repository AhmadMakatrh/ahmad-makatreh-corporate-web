# لوحة إدارة الموقع

> سجل تنفيذ تاريخي. خريطة التشغيل الحالية في [معمارية المشروع الحالية](current-architecture.md). لوحة الإدارة تعمل الآن عبر Worker مستقل، وتستخدم D1 وSupabase بدل مسار PostgreSQL الموصوف في أجزاء من هذا السجل.

تم تنفيذ المصدر في `client/src/admin/` مع API محمي وطبقة حفظ PostgreSQL. نطاق التشغيل المقصود هو `admin.ahmad-makatreh.vip`. لم تُغيّر إعدادات Cloudflare أو قاعدة الإنتاج، ولم يُنشر هذا التعديل.

## الاستخدام

- **الطلبات:** تصفية بالاسم والبريد والمرجع والفئة والحالة ونتيجة إشعار البريد والتاريخ، مع 25 طلبًا في الصفحة. تفتح الرسالة كاملة عند اختيارها وتُحفظ الحالة والملاحظات الخاصة بزر مستقل. الرد يدوي إلى بريد الطلب المحفوظ، مع سجل 25 ردًا ونتيجة SMTP. يمكن تصدير طلبات الصفحة JSON/CSV واستعادة حتى 100 سجل مفقود لكل ملف دون تغيير الموجود أو إرسال بريد.
- **الأسعار والعروض:** إنشاء الباقات والعروض، تحرير اللغتين والأسعار والمزايا، ترتيبها وإخفاؤها، وتحديد بداية العرض ونهايته والباقات المشمولة والنافذة المنبثقة. ترتبط الباقة الجديدة بنموذج التواصل.
- **المحتوى والصور:** تحرير النصوص العربية والإنجليزية وصور الهوية، وإنشاء/حذف/ترتيب/إخفاء الأعمال والمقالات. العمل الجديد يملك صفحة تفاصيل مرتبطة بمساره. المقال الجديد أو محتواه المعدّل نص آمن؛ تغيير عنوان المقال الأصلي أو ترتيبه يحافظ على تنسيقه الموثوق.
- **مكتبة الوسائط:** رفع صريح واختيار PNG/JPEG/WebP/PDF حتى 10 MiB، 25 ملفًا لكل صفحة. التخزين ملفات محلية فعلية في Development وR2 في الإنتاج بعد إعداد الأسرار. لا تُقبل بيانات ملف قبل نجاح التخزين. الإزالة من المكتبة تُرفض إذا استُخدم الملف في مسودة أو منشور، وتحفظ الملف الأصلي للحفاظ على روابط التاريخ ومنع سباق النشر المتزامن.
- **الصفحات:** قوالب تعريفية وخدمية، وأقسام عنوان/نص/صورة/بطاقات/دعوة للتواصل قابلة للترتيب. يمكن معاينة المسودة باللغتين، وتحديد الرابط وظهورها في القائمة، وتعديل عنوان ووصف نتائج البحث.
- **الحفظ والنشر:** الحفظ يغيّر المسودة فقط. النشر إجراء مستقل، وتُحتفظ نسخة منشورة سابقة يمكن استعادتها. محاولة نشر النسخة نفسها لا تمحو النسخة السابقة. تعارض التعديل من جلسة أخرى يرفض الحفظ بدل الكتابة فوقه. سجل النسخ يحمل العملية والمالك والوقت؛ استعادة نسخة تسجل رقم مصدرها وتُنشئ مسودة جديدة. التسجيل يبدأ من تفعيل الميزة.
- **النسخ الاحتياطي والخروج:** تنزيل مستندات المحتوى والأسعار والصفحات واستعادة مستند واحد إلى المسودة بعد مراجعة النسخة الحالية وتأكيد العملية. نسخة المستندات لا تشمل تاريخ القاعدة أو ملفات R2. الخروج يستخدم `/cdn-cgi/access/logout`؛ إلغاء الخروج أثناء وجود مسودة يحافظ عليها.

## ميزانية الطلبات والاستعلامات

أعداد PostgreSQL أدناه مستنتجة من مسارات المستودعات، وليست قياسًا لقاعدة حقيقية. يفرّق الجدول أوامر القاعدة عن الصفوف المكتوبة، ويستثني إعادة محاولات القراءة عند أعطال الاتصال. طلبات الملفات والخطوط والصور ومفاتيح Cloudflare لا تعد استعلامات قاعدة.

| العملية | طلبات HTTP | استعلامات القاعدة |
|---|---:|---:|
| التحقق من الدخول ورمز CSRF | 1 عند دخول اللوحة | 0 |
| عرض صفحة طلبات أو تطبيق تصفية جديدة | 1 | 1 قراءة محدودة |
| فتح تفاصيل طلب غير موجود في ذاكرة الجلسة | 1 | 1 قراءة |
| تغيير حالة طلب | 1 PATCH | 1 تحديث مشروط |
| فتح محرر الأسعار أو المحتوى أو الصفحات | 1 لكل مستند غير محفوظ مؤقتًا | 1 قراءة |
| الكتابة والبحث المحلي وترتيب الأقسام والمعاينة | 0 | 0 |
| حفظ المسودة | 1 PUT | 1 أمر ذري: تحديث المستند + إدراج نسخة التاريخ |
| نشر المسودة أو استعادة المنشور السابق | 1 POST | 1 أمر ذري: تحديث المستند + إدراج نسخة التاريخ |
| عرض صفحة تاريخ | 1 عند النقر | 1 قراءة حتى 26 ملخصًا لإظهار 25 |
| استعادة نسخة تاريخ إلى المسودة | 1 POST | قراءة النسخة + أمر كتابة ذري للمستند والتاريخ |
| تنزيل نسخة المستندات | 1 GET | 1 قراءة حتى 3 مستندات |
| استعادة مستند من ملف | GET مراجعة ثم PUT مؤكد | قراءة + أمر كتابة ذري؛ باقي المستندات محفوظة |
| عرض صفحة الوسائط | 1 GET | 1 قراءة حتى 26 سجلًا |
| رفع ملف جديد | 1 POST | قراءة معرّف + إدراج metadata؛ عملية رفع R2 واحدة |
| إعادة الرفع بنفس المعرّف والملف | 1 POST | 1 قراءة، 0 كتابة و0 رفع R2 |
| اختيار ملف أو معاينة المقال | 0 | 0 |
| إزالة ملف من المكتبة | 1 POST | قراءتان (ملف + حتى 3 مستندات) وتحديث واحد؛ لا حذف R2 |
| حفظ ملاحظة | 1 PATCH | 1 تحديث مشروط |
| رد جديد | 1 POST | قراءتان + حجز المعرّف + تسجيل النتيجة؛ محاولة SMTP واحدة |
| تكرار طلب الرد بنفس المعرّف | 1 POST | 1 قراءة، لا إرسال SMTP إضافي |
| عرض صفحة سجل الردود | 1 GET عند النقر | 1 قراءة حتى 26 سجلًا |
| تصدير JSON/CSV | 1 POST | 1 قراءة لمعرّفات مختارة حتى 100 |
| استيراد الطلبات المفقودة | 1 POST | قراءة المعرّفات الموجودة + إدراج المفقود داخل معاملة محدودة بـ100 سجل |
| تحميل محتوى الموقع العام | 1 لكل تحميل للواجهة | 0 داخل صلاحية ذاكرة الخادم، وإلا 1 قراءة لجميع المستندات المنشورة |
| تغيير لغة الموقع والتنقل من قائمته داخل الواجهة | 0 طلبات محتوى إضافية | 0 |

لا يوجد polling أو autosave أو طلب مع كل ضغطة مفتاح أو استعلام مستقل لعدّ جميع الطلبات. قوائم الطلبات تستخدم cursor وحجم الصفحة + سجل واحد لتحديد وجود صفحة تالية؛ لا تُحمّل الرسائل الكاملة داخل القائمة.

في السباقات قد تضيف محاولة الرفع الخاسرة قراءة إضافية وتنظيف ملفها المؤقت؛ ومحاولة الرد المتزامنة الخاسرة تقرأ سجل العملية بدل إعادة البريد. SMTP لا يضمن معرفة النتيجة إذا انقطع الاتصال بعد قبول الرسالة: pending/unknown تبقى بلا إعادة إرسال، ويحتاج بدء رد جديد تأكيدًا صريحًا. منع التكرار مرتبط بمعرّف العملية نفسه، وليس ضمانًا مطلقًا عبر ردود جديدة بمعرّفات مختلفة.

طلبات GET في الإدارة تتشارك الطلب الجاري وتُحفظ في ذاكرة الجلسة 60 ثانية، بحد أقصى 40 نتيجة، دون تخزين بيانات الطلبات في localStorage. الحفظ يحدّث العرض المحلي دون إعادة GET ويُبطل النتائج المتعلقة بالعملية فقط؛ حفظ الأسعار لا يُبطل محرر المحتوى أو الصفحات. رفع/إزالة الوسائط والرد على البريد لا يُبطلان قائمة الطلبات، والتصدير للقراءة لا يُبطل الذاكرة. الملاحظات والحالة والاستيراد تُبطل قوائم الطلبات لأنها تغيّر بياناتها. التحديث اليدوي يتجاوز الذاكرة. الإخفاق لا يسبب إعادة محاولات تلقائية.

المحتوى العام يحفظ في ذاكرة كل API instance لمدة 30 ثانية مع ETag وHTTP max-age=30. النشر يبطل ذاكرة النسخة التي عالجته؛ النسخ الأخرى تتجدد عند انتهاء المدة. مع وجود أكثر من طبقة تخزين مؤقت قد يتأخر ظهور النشر قرابة 60 ثانية؛ الصفحات المفتوحة تحتاج إعادة تحميل. تغيّر مواعيد العروض يُحسب محليًا دون طلب جديد.

نموذج التواصل يرسل جميع الحقول في **طلب POST واحد**. حفظ الطلب ومنع التكرار يستعملان آلية الحماية الموجودة؛ تُضاف كتابة مستقلة ضرورية لتسجيل نتيجة إشعار البريد، ولا يعاد إرسال البريد عند تغيير حالة الطلب. التحقق من مفتاح باقة جديدة يستخدم نسخة الأسعار المنشورة المخزنة مؤقتًا، بينما المفاتيح الأصلية لا تضيف قراءة محتوى.

## إعداد التشغيل الفعلي

1. احمِ كامل `admin.ahmad-makatreh.vip` بتطبيق Cloudflare Access، بما فيه `/api/admin/*`، مع سياسة تسمح بحساب المالك فقط. إعداد MFA يتبع مزود الهوية المختار.
2. اضبط متغيرات API التالية بالقيم الفعلية، خارج المستودع:

   ```text
   AdminAccess__TeamDomain=https://YOUR-TEAM.cloudflareaccess.com
   AdminAccess__Audience=YOUR-ACCESS-APPLICATION-AUD
   AdminAccess__AllowedEmails__0=YOUR-ADMIN-EMAIL
   AdminAccess__Origin=https://admin.ahmad-makatreh.vip
   ```

   يتحقق الخادم من توقيع RS256 والجهة والجمهور والانتهاء والبريد المصرح ونوع رمز التطبيق. غياب الإعدادات يرفض الدخول. يرفض الحفظ من Origin مختلف أو دون CSRF صحيح. لا يوجد تجاوز دخول محلي. [توثيق التحقق من Access](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/)

3. اضبط `API_ORIGIN` في Worker إلى أصل API ثابت عبر HTTPS، دون مسار، مثل أصل API المعتمد لديك. يحوّل `client/worker.js` طلبات الإدارة فقط، ويمرر assertion وملف CSRF دون تمرير بقية ملفات الدخول أو اتباع تحويلات الخادم.
4. نموذج إعدادات الخادم موجود في `server/.env.example`؛ مرجع للأسماء فقط، لا يقرأه ASP.NET تلقائيًا. ضعه في إعدادات البيئة/الأسرار الخاصة بالمضيف. جهّز PostgreSQL مستقلًا وSMTP على 587 مع StartTLS، وR2 بصلاحية bucket الموقع ورابط HTTPS عام للمواد العامة. إعدادات Worker `API_ORIGIN` وأصل API العام `VITE_API_BASE_URL` منفصلان عن إعدادات الخادم.
5. طبّق جميع ترحيلات EF بعد النسخ الاحتياطي والتحقق في بيئة معزولة. `server/migrations/002_admin_completion.sql` idempotent **تكميلي** يفترض وجود ترحيلات المشروع حتى `20261011081736_AddSiteDocuments`؛ يضيف التاريخ والوسائط والملاحظات والردود فقط. قاعدة جديدة تحتاج سلسلة EF كاملة من البداية. لا تحذف ترحيلات الحماية السابقة أو بيانات الطلبات، ولا تعكس الترحيلات بعد استعمال البيانات الجديدة دون خطة استعادة.
6. في بيئة متعددة النسخ، شارك مفاتيح ASP.NET Data Protection واحفظها بصورة دائمة حتى لا تتعطل رموز CSRF عند إعادة التشغيل أو تبديل الخادم. استمر في إعدادات PostgreSQL وTurnstile وحماية IP والبريد الموجودة. حد الإدارة 120 طلبًا/دقيقة لكل هوية، والرفع والرد 6/دقيقة لكل منهما. تحتاج حماية الحافة أيضًا؛ هذه حدود لكل API instance وليست قياس سعة أو بديل WAF.
7. اختبر الدخول الحقيقي والخروج والحفظ والنشر واستعادة النسخة والطلبات مع PostgreSQL في بيئة اختبار قبل إطلاق نطاق الإدارة. أصل API يحتاج مضيفًا يدعم .NET 10؛ Worker الحالي يوجه طلبات الإدارة ولا يشغّل ASP.NET. القبول من مزود البريد لا يثبت وصول الرسالة إلى صندوق الوارد.

## النسخة الكاملة والاستعادة

نسخة واجهة الإدارة قابلة للنقل لكنها لا تحل محل نسخة PostgreSQL والوسائط. قبل أخذ نسخة كاملة، أوقف عمليات الإدارة التي تغيّر المحتوى/الوسائط مؤقتًا، وخذ `pg_dump -Fc` ببيانات اتصال آمنة خارج الأوامر والمستودع. تُستعاد إلى قاعدة جديدة معزولة بواسطة `pg_restore --exit-on-error --no-owner`، وتراجع المستندات والتاريخ والطلبات والردود قبل أي تحويل إنتاج. تنسيق custom يستعمل pg_restore؛ تفاصيل الأدوار تحتاج نسخة منفصلة عند نقل الخادم. [توثيق PostgreSQL](https://www.postgresql.org/docs/16/backup-dump.html)

انسخ كائنات R2 وmetadata (المفتاح وContent-Type وContent-Disposition وCache-Control) إلى وجهة منفصلة باستخدام S3/Rclone؛ لا تستخدم مزامنة تحذف الملفات من الوجهة. قارن حجم/SHA256 الكائنات المسجلة مع `media_assets`، واحتفظ أيضًا بالأصول المؤرشفة وبملفات لم يُحسم حفظ metadata لها عند انقطاع الاتصال. عند الاستعادة استخدم مفاتيح الكائنات نفسها ورابط media العام نفسه، أو راجع تحويل الروابط في بيئة الاختبار قبل النشر. أسرار R2 وSMTP وAccess ومفاتيح Data Protection تُحفظ خارج نسخة المحتوى في مدير الأسرار. [R2 و.NET SDK](https://developers.cloudflare.com/r2/examples/aws/aws-sdk-net/)

لم تُنفّذ استعادة كاملة لقاعدة أو bucket حقيقيين بعد؛ Docker المحلي متوقف ورفضت مراجعة الأوامر الآلية تشغيله. لا تعتبر إجراء النسخ موثوقًا تشغيليًا قبل تجربة الاستعادة المعزولة.

## محليًا والتحقق

واجهة الإدارة المحلية: `http://admin.localhost:5173/`. بدون assertion صالح تظهر حالة «الدخول مطلوب»؛ هذه نتيجة الحماية المقصودة. يمكن تشغيل API بـ Development وموفر Json للاختبارات المحلية فقط. يرفض المشروع هذا الموفر في Production.

الاختبارات الخادمية تستخدم JWT موقّعًا ومفاتيح اختبار وموفر JSON محليًا. اختبار المتصفح الكامل يستخدم بيانات شبكة معزولة للاختبار؛ لا يوجد mock أو تخطي صلاحيات داخل المنتج. اختبار الدخول غير المهيّأ استعمل API المحلي الحقيقي. PostgreSQL الفعلي وإعداد Access على الحساب لم يُختبرا بعد.

هناك 7 إخفاقات سابقة في اختبارات الحجز/تهيئة الإنتاج مرتبطة بحماية IP وHMAC، وتحذيرات lint سابقة. حُدّثت MailKit إلى 4.16.0 (وMimeKit التابعة لها) لأن مسار الرد الجديد يتأثر بثغرة STARTTLS في الإصدار السابق. لم تتغير حزم غير لازمة لهذا الإصلاح. [تنبيه MailKit](https://github.com/jstedfast/MailKit/security/advisories/GHSA-9j88-vvj5-vhgr)، [تنبيه MimeKit](https://github.com/jstedfast/MimeKit/security/advisories/GHSA-g7hc-96xr-gvvx)

التحقق الحديث: العميل/Worker 14/14، API الإدارة 19/19، التحقق من المستندات 17/17، وبناء الواجهة وAPI وlint الإدارة ناجحة. اختبار متصفح معزول نفّذ 19 عملية HTTP تغطي الملاحظات وإعادة التحقق بعد فشل الشبكة والرفع والاختيار والتصدير والتاريخ والاستعادة؛ صفر طلبات أثناء التحرير أو إلغاء الاستعادة. نشر تفاصيل Elpha Reader دون label وعرضها نجح، والسلايدر بعد تحميل المحتوى يقلب خلال 3 ثوانٍ، والهاتف RTL بلا overflow. اختبارات SMTP تستخدم خادم TCP محليًا فعليًا وتؤكد accepted/unknown، واختبار الرفع يقرأ PNG المخزّن فعليًا، وفشل مخزن محلي حقيقي يرجع 503 دون metadata. المراجعة المصدرية المستقلة وجدت خطأين مهمين وأُصلحا؛ إعادة المراجعة لم تجد ملاحظات مهمة متبقية في التغييرات المراجعة. تُرجمت استعلامات صفحات الوسائط والردود إلى SQL مع cursor ودونه، واجتازت نسخة محرر فعلية تحقق الخادم؛ هذا لا يثبت تنفيذ SQL على PostgreSQL.

المجموعة الخادمية الأوسع (باستثناء اختبارات PostgreSQL القديمة التي تشير لقاعدة اسمها prod) كانت 116 ناجحًا و7 إخفاقات سابقة. الوصول إلى PostgreSQL/R2/Access الحقيقي ووصول البريد لصندوق المالك غير مختبر. فحص Wrangler السابق كان dry-run دون نشر. اختبار 100 قراءة متزامنة للمحتوى استخدم قراءة واحدة من المستودع. هذه قياسات محلية، وليست إثباتًا لسعة الإنتاج.
