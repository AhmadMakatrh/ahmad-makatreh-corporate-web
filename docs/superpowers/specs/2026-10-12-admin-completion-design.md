# إكمال لوحة إدارة الموقع

## التفويض والنطاق

طلب المالك إكمال جميع النواقص المذكورة بتاريخ 2026-10-12، على مراحل قابلة للاستئناف. يشمل ذلك الوسائط، إنشاء/حذف/ترتيب الأعمال والمقالات، سجل النسخ والتعديلات والنسخ الاحتياطي، تسجيل الخروج، ملاحظات الطلبات والرد والتصدير، والتحقق من التشغيل الحقيقي. البنية المعتمدة تبقى React داخل `client/src/admin/` و.NET/PostgreSQL مع Cloudflare Access على `admin.ahmad-makatreh.vip`.

## القيود

- لا تفقد أو تستبدل التغييرات السابقة غير المحفوظة في Git. لا commit أو push أو تبديل فرع تلقائيًا.
- لا تخطي للمصادقة المحلية أو الإنتاجية. لا أسرار في المصدر أو رسائل المحادثة.
- لا polling أو autosave أو استعلام أثناء الكتابة والمعاينة. التحميل عند فتح القسم؛ الحفظ والنشر والرفع والتصدير بأفعال صريحة.
- النشر الخارجي وترحيل قاعدة الإنتاج لا يحدثان تلقائيًا؛ تجهز الملفات والاختبارات أولًا، ويؤكد المالك بيئة التشغيل والإجراء النهائي.
- تحفظ البنية القديمة للمحتوى والروابط. البيانات الجديدة المنظمة اختيارية داخل مستند المحتوى، ويظل المستند القديم مقروءًا دون ترحيل مدمر.
- الملفات المرفوعة صور PNG/JPEG/WebP وPDF، بحد 10 MiB للملف، أسماء تخزين عشوائية، فحص توقيع المحتوى ومنع HTML/SVG والملفات التنفيذية. لا يجلب الخادم روابط يحددها المستخدم.

## المراحل والتصميم

1. **الجلسة والخروج:** زر خروج عبر مسار Cloudflare Access الخاص بالتطبيق، مع استمرار تحذير التعديلات غير المحفوظة. لا استعلام للقاعدة ولا نظام دخول جديد.
2. **الأعمال والمقالات:** محررات مفهومة للإضافة والتحرير والترتيب والإخفاء والإزالة من المسودة؛ تتصل بالمحتوى المنشور نفسه. تحقق خادمي من الحقول والروابط والتكرار والحدود، وعرض المقالات الجديدة كنص آمن. المعاينة والفرز محليان.
3. **النسخ والتدقيق والنسخ الاحتياطي:** نسخ محتوى مؤرخة ومحددات متزايدة، حفظ سجل العملية والمالك مع الكتابة نفسها داخل معاملة؛ قائمة تاريخ محدودة cursor؛ الاستعادة تنشئ مسودة جديدة ولا تمحو التاريخ. تصدير واستيراد نسخة بيانات إدارية واضحة الإصدار مع تحقق كامل وحماية التعارض. نسخة البيانات لا تتضمن الأسرار أو مفاتيح الحماية أو ملفات الوسائط؛ نسخة قاعدة كاملة وملفاتها موثقة ومختبرة بوسائل PostgreSQL/R2، دون تشغيلها على الإنتاج تلقائيًا.
4. **الوسائط:** مكتبة محدودة بصفحات، رفع ملف واحد في طلب صريح، تخزين R2 الإنتاجي وملفات محلية في Development فقط؛ حفظ بيانات الملف بعد نجاح التخزين. اختيار صورة من المكتبة يملأ الحقل بلا طلب إضافي. لا حذف ملف منشور مستخدم، ولا اعتماد ملف ناقص عند فشل التخزين.
5. **عمليات الطلبات:** ملاحظات داخلية محفوظة صراحة، تصدير محدود للنتائج، إرسال رد بالبريد عبر خدمة البريد المعتمدة مع سجل المحاولة ومنع النقر المكرر/تكرار المفتاح. لا إرسال أو إعادة إرسال عند تعديل الحالة. قبول SMTP يعرض كقبول إرسال لا تأكيد وصول صندوق الوارد.
6. **التحقق والربط الفعلي:** اختبارات PostgreSQL على قاعدة معزولة، المصادقة وCSRF، الربط العام، وقياس الطلبات. تجهيز SQL idempotent وتشغيل Access/API/R2/SMTP يعتمد على إعدادات المالك خارج المصدر. لا ادعاء اكتمال التشغيل إذا كانت موارد الحساب غير متاحة.

## قبول العمل

كل مرحلة تحقق مسار UI → API → تخزين/خدمة حقيقية → أخطاء، واختبارات تلقائية ثم build وlint ودiff. تضاف نتيجة التنفيذ وملفاته والأوامر إلى `docs/admin-completion-progress.md` فور انتهاء المرحلة. يستأنف العمل بعد اختصار السياق من أول مربع غير مكتمل، دون إعادة كتابة المراحل المنجزة.

## حدود التشغيل المعروفة

لم يتأكد أصل API الفعلي أو PostgreSQL أو R2 أو SMTP على حساب المالك. سُئل المالك عن الخدمات والعناوين فقط، دون طلب أسرار. يمكن إكمال الكود والتحقق المحلي المستقل أثناء انتظار تلك المعلومات؛ اختبار موارد الإنتاج يبقى خطوة منفصلة.
