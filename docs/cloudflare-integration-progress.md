## نقطة الاستئناف

طلب المالك تجهيز خيار Cloudflare والمساعدة في إعداد كل ما يمكن، مع سؤاله عن الحسابات. اعتمد التصميم وخطة المرحلة الأولى وحد 9 محاولات لكل IP خلال 60 ثانية بتاريخ 2026-10-12. نُفذت مهام المرحلة الأولى داخل `server/cloudflare/` واكتملت المراجعة المحلية المستقلة وإصلاح ملاحظاتها واختباراتها. اختار المالك حساب Cloudflare الحالي، وأكد وجود حساب Brevo وحدد بريد الاستقبال؛ جاهزية الصندوق وهوية دخول الإدارة وتوثيق مرسل Brevo ما زالت معلقة. أُنشئت الآن D1 للمعاينة فقط، دون بيانات مستخدمين أو ربط إنتاج. اختبارات المتصفح والخدمات الخارجية والإنتاج تبقى شروطًا مفتوحة لمرحلة الربط.

للاستئناف: اقرأ هذا السجل وملحق Supabase وخطة5B و`server/cloudflare/README.md` وسجل التنفيذ `.superpowers/sdd/2026-10-13-supabase-storage-phase-5b/progress.md`. التصميم والوثيقة والخطة والتنفيذ المباشر معتمدة؛ لا تعِد سؤال الاعتماد أو المهام1–3 المكتملة. التالي تأكيد حاويةSupabase الخاصة وسياساتها والسر داخل Cloudflare، ثم نشرWorker المعاينة والتحقق المستضاف وفق الخطة. لا تعِد إنشاء D1 أو تطبيق الترحيلات المكتملة، ولا تعِد تنفيذ الواجهة أو تعديل.NET أو حذف التغييرات السابقة. إعداد المعاينة يحفظالحساب وUUID والمحددات والطرق/cron الفارغة مع مزودSupabase؛ لا فوترة أو تفعيلR2 أو نشرإنتاج.

## ما أُنجز وما لم يُنجز

تخطيط Supabase بتاريخ2026-10-13: زوّد المالك عنوان `https://kghmejpjvbmcivnlnkgf.supabase.co` ولقطة مشروع **Ahmad Porto** ضمن **RUQOSH** مع شارةFree وقائمة Storage خالية من الحاويات. اعتمد التصور ثم الملحق المكتوب، وجُهزت خطة5B وتنتظر مراجعته. لا حساب PostgreSQL للتطبيق أو تغيير UI؛ الوصلة المقترحة تحفظ R2 المحلي والعقود وUUID وتستهدف2SQL للرفع الجديد و1للمكتبة/إعادة محاولة مطابقة، مع بيان العمليات الإضافية عند التزامن وmetadata الداخلية لـSupabase. حاوية `ahmad-makatreh-media-preview` وحاوية الاستعادة `ahmad-makatreh-media-restore-preview` اسمان مخططان خاصان؛ لم تُنشآ، ولم يُدخل سر أو يُغيّر إعداد المعاينة أو يُنشر Worker. أدوات التحكم بـEdge تعطلت قبل قراءة الصفحة؛ لا استنتاج صلاحية حساب/مفتاح من الرابط أو اللقطة. اختبار الملفات الخاصة وسياسات publishable-key يسبق الربط العام، والنسخ تحتاج بايتات الملفات منفصلة عن قاعدة البيانات. لم يُنفذ أو يُختبر مسار Supabase بعد؛ تغييرات هذه الخطوة توثيق فقط.

تجهيز5A بتاريخ2026-10-12: الحساب نفسه مؤكد؛ أُنشئت D1 `ahmad-makatreh-preview` بمعرف `7b1d12c7-8d63-49c2-b9ec-fec22dfc5f3f` فيWEUR. طُبقت0001–0004 مرة واحدة؛ الجداول الثمانية فارغة. محاولة التحقق الأولى رفضت9فروعUNION برمز7500؛ استعلامSELECT واحد بقراءات فرعية نجح بـ4صفوف مقروءة وصفر كتابة. هذه إجراءات تجهيز صريحة، دون polling. إعداد `server/cloudflare/wrangler.preview.jsonc` يعطل workers.dev/previewURLs والطرق وcron، ويشير إلى D1 الحقيقي واسم R2 المخطط فقط. اختبارات حراسة الإعداد الجديدة فشلت لغياب الملف ثم نجحت4/4؛ المجموعة المحلية كاملة127/127 بلا تخطي أو فشل، وبناء المعاينة dry-run نجح160.27KiB/gzip39.80KiB. إصدار الموقع الإنتاجي بقي `fce28771-76c9-469e-a461-a399388a996c`، وبصمات إصلاحات.NET محفوظة. R2 غير مفعّل ولا bucket أو Worker جديد منشور، ولا جاهزية تشغيل فعلية قبل بقية الربط والمراجعة المستقلة النهائية. رفض المالك إضافة وسيلة دفع؛ لا تغيير اشتراك أو بيانات دفع أو أسرار.

تنفيذ المرحلة الرابعة محليًا: أُضيف ترحيل الوسائط ومسارات R2 مع الواجهة الحالية. القياس: القائمة SELECT واحد حتى26صفًا دون COUNT أو قائمة R2؛ رفع جديد2SQL وPUT واحد؛ إعادة محاولة مطابقة1SQL دون PUT؛ أرشفة3–9SQL مع حماية revision واحتفاظ الملفات التاريخية. لا polling أو autosave أو طلبات لكل حقل. الاستعادة الفعلية إلى موارد محلية فارغة طابقت8جداول و103ملفات وHTTP/custom metadata والبيانات العربية والتاريخ وInt64. اكتشف التصدير المحلي لـWrangler تقريب Int64؛ استُعمل تصدير SQLite الأصلي للقراءة فقط ثم استيراد SQL عبر Wrangler، مع بقاء فحص التصدير السحابي للمرحلة الخامسة. الخادم123/123 والعميل16/16 والبناءان ناجحان، وتحذيرات lint العميل التسعة سابقة. المراجعة المستقلة لم تجد ملاحظات حرجة أو مهمة أو ثانوية؛ حُفظ تقريرها والسجل والأدلة محليًا. إصلاحات .NET الأربع بقيت ببصماتها الأصلية. الحسابات والنطاق والمتصفح الحقيقي وCPU والاستعادة السحابية لم تُختبر، ولم يحدث commit أو نشر.
